## 3. Kiến thức quan trọng / Keyword cần nắm

Danh sách khái niệm PHẢI hiểu được (không chỉ copy-paste code) trước khi coi buổi này là xong:

- **Docker networking (service name = hostname)** — 2 container trong cùng `docker-compose.yml` tự thấy nhau qua tên service (vd Postgres tên service `postgres` thì container khác connect bằng host `postgres`, không phải `localhost`). Từ máy host (script Python chạy ngoài Docker) thì connect qua `localhost:<port đã map>`.
- **Schema vs Database trong Postgres** — 1 database Postgres chứa nhiều schema (namespace); `raw` là 1 schema trong database mặc định (vd `olist`), không phải 1 database riêng. Dùng schema để tách raw data khỏi các layer sau này (staging, marts) khi làm dbt ở buổi sau.
- **Idempotent load** — chạy lại script ingest nhiều lần phải ra kết quả giống nhau, không bị nhân đôi data. Cách làm: `TRUNCATE TABLE raw.<table>` trước khi load lại (nhanh, giữ nguyên structure/index), tránh dùng `DROP TABLE` + tạo lại trừ khi schema đổi.
- **`COPY` command** — lệnh native Postgres để bulk-load dữ liệu dạng CSV vào table, nhanh hơn nhiều so với insert từng row (bao gồm cả `pandas.to_sql` mặc định). Cơ chế: stream data trực tiếp qua wire protocol, không parse SQL statement cho từng row → phù hợp cho file lớn (Olist có file `order_items`, `order_reviews` hàng chục nghìn dòng).
- **`COPY` vs `pandas.to_sql`** — benchmark thực tế: `psycopg2` `copy_from`/`copy_expert` nhanh hơn `to_sql` khoảng 10-13x trên dataset ~1M dòng (vd 51s → 13s, hoặc 4 phút → 18s tuỳ trường hợp). Buổi này ưu tiên `COPY` cho performance, `pandas` chỉ dùng để đọc/inspect CSV.
- **Connection reuse (không phải pool phức tạp)** — script ingest 1 lần chạy xong thì đóng connection, không cần connection pool (pgbouncer, SQLAlchemy pool...) ở mức này — biết khái niệm để không over-engineer.

## 4. Các bước nhỏ (step-by-step)

1. **Tạo cấu trúc thư mục project**
   - Tạo layout gọn cho buổi này, vd:
     ```
     ingest/
       docker-compose.yml
       .env
       ingest.py
       data/olist/*.csv   (9 file CSV đã download)
     ```
   - Kỳ vọng: có sẵn thư mục `data/olist/` chứa đủ 9 file CSV gốc (`olist_orders_dataset.csv`, `olist_customers_dataset.csv`, `olist_order_items_dataset.csv`, `olist_order_payments_dataset.csv`, `olist_order_reviews_dataset.csv`, `olist_sellers_dataset.csv`, `olist_geolocation_dataset.csv`, `olist_products_dataset.csv`, `product_category_name_translation.csv`).

2. **Viết `docker-compose.yml` (Postgres + pgAdmin)**
   - Skeleton (Compose V2, biến nhạy cảm đọc từ `.env` cùng thư mục — KHÔNG hardcode password):
     ```yaml
     services:
       postgres:
         image: postgres:18
         environment:
           POSTGRES_USER: ${POSTGRES_USER}
           POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
           POSTGRES_DB: ${POSTGRES_DB}
         ports:
           - "5432:5432"
         volumes:
           - pgdata:/var/lib/postgresql/data
         healthcheck:
           test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER}"]
           interval: 5s
           retries: 5

       pgadmin:
         image: dpage/pgadmin4:9.8
         environment:
           PGADMIN_DEFAULT_EMAIL: ${PGADMIN_EMAIL}
           PGADMIN_DEFAULT_PASSWORD: ${PGADMIN_PASSWORD}
         ports:
           - "5050:80"
         depends_on:
           - postgres

     volumes:
       pgdata:
     ```
   - Chạy: `docker compose up -d`.
   - Kỳ vọng: `docker compose ps` show 2 container `Up` (postgres, pgadmin); mở `http://localhost:5050` login được pgAdmin, add server mới trỏ host `postgres` (tên service, không phải `localhost` — vì pgAdmin connect từ trong network Docker) port `5432`.
   - ⚠️ Lỗi thường gặp: port `5432` bị chiếm (có Postgres khác chạy sẵn trên máy) → đổi port map bên trái, vd `"5433:5432"`, và sửa lại connection string script Python tương ứng.

3. **Tạo schema `raw` trong Postgres**
   - Connect vào DB (qua pgAdmin Query Tool, hoặc `psql`), chạy: `CREATE SCHEMA IF NOT EXISTS raw;`
   - Kỳ vọng: schema `raw` xuất hiện trong tree pgAdmin dưới database.

4. **Viết `ingest.py` — logic nạp CSV vào `raw`**
   - Outline (pseudocode, không phải code chạy full):
     ```python
     import csv, os, psycopg2

     TABLES = {
         "raw.customers": "olist_customers_dataset.csv",
         "raw.orders": "olist_orders_dataset.csv",
         "raw.order_items": "olist_order_items_dataset.csv",
         "raw.order_payments": "olist_order_payments_dataset.csv",
         "raw.order_reviews": "olist_order_reviews_dataset.csv",
         "raw.products": "olist_products_dataset.csv",
         "raw.sellers": "olist_sellers_dataset.csv",
         "raw.geolocation": "olist_geolocation_dataset.csv",
         "raw.product_category_translation": "product_category_name_translation.csv",
     }

     def get_columns_from_csv_header(path): ...  # đọc dòng đầu CSV để tạo cột TEXT hết (raw layer không cần ép type)

     def ensure_table(cur, table, columns): ...
         # CREATE TABLE IF NOT EXISTS <table> (<col1> TEXT, <col2> TEXT, ...)

     def load_table(cur, table, csv_path):
         cur.execute(f"TRUNCATE TABLE {table}")   # idempotent — xoá data cũ trước khi load lại
         with open(csv_path, "r", encoding="utf-8") as f:
             next(f)  # skip header
             cur.copy_expert(f"COPY {table} FROM STDIN WITH CSV", f)

     def main():
         conn = psycopg2.connect(host=..., port=..., dbname=..., user=..., password=...)
         cur = conn.cursor()
         for table, filename in TABLES.items():
             columns = get_columns_from_csv_header(os.path.join(DATA_DIR, filename))
             ensure_table(cur, table, columns)
             load_table(cur, table, os.path.join(DATA_DIR, filename))
         conn.commit()
     ```
   - Điểm quan trọng: raw layer nên load mọi cột dạng `TEXT` (không ép kiểu ngay) — type casting/validation là việc của staging layer (dbt, buổi P1.S02), raw chỉ cần đúng data gốc.
   - Dùng `cur.copy_expert("COPY ... FROM STDIN WITH CSV", file_handle)` (đọc trực tiếp file, không qua StringIO trung gian) vì nhanh và đơn giản hơn `copy_from` khi file đã đúng format CSV chuẩn.
   - Kỳ vọng: chạy `python ingest.py` không lỗi, log ra số dòng đã load mỗi table (thêm `print` đơn giản là đủ, không cần logging framework).
   - ⚠️ Lỗi thường gặp: file CSV Olist encode `utf-8` nhưng có dòng chứa ký tự đặc biệt (dấu tiếng Bồ Đào Nha) → nếu lỗi decode, mở file với `encoding="utf-8-sig"` hoặc kiểm tra BOM.
   - ⚠️ Lỗi thường gặp: `order_reviews` có field text chứa dấu phẩy/newline trong review comment → `COPY ... WITH CSV` tự xử lý quote đúng chuẩn RFC 4180, nhưng nếu file gốc không quote đúng thì phải tiền xử lý bằng `pandas.read_csv` rồi export lại CSV chuẩn trước khi `COPY`.

5. **Verify idempotent — chạy lại lần 2**
   - Chạy `python ingest.py` lần thứ 2 ngay sau lần đầu.
   - Kỳ vọng: số dòng mỗi table giống lần 1 (không nhân đôi) — chứng minh `TRUNCATE` trước load hoạt động đúng.

6. **Kiểm tra data trong pgAdmin**
   - Query Tool: `SELECT COUNT(*) FROM raw.orders;`, `SELECT * FROM raw.customers LIMIT 10;`
   - Kỳ vọng: số dòng khớp số dòng CSV gốc (trừ header), data hiển thị đúng encoding (không lỗi ký tự lạ).
