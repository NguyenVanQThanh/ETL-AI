## 3. Kiến thức quan trọng / Keyword cần nắm

- **RAG (Retrieval-Augmented Generation) cho schema linking** — RAG thường dùng để retrieve *document* liên quan rồi nhồi vào prompt; ở đây áp dụng khác: đối tượng retrieve là **schema metadata** (bảng/cột), không phải văn bản tự do. Mục tiêu là "schema linking" — tìm đúng phần schema liên quan tới câu hỏi, thay vì luôn nhồi toàn bộ `dictionary.json` (cách A1 đang làm).
- **Embedding vector** — biểu diễn số (mảng float, ở đây 384 chiều) của một đoạn text, sao cho 2 đoạn text có nghĩa gần nhau thì vector cũng gần nhau trong không gian vector.
- **Cosine similarity** — đo độ gần giữa 2 vector theo góc (không theo khoảng cách tuyệt đối). pgvector dùng operator `<=>` để tính **cosine distance** (0 = giống hoàn toàn, 2 = ngược hoàn toàn); similarity = `1 - distance`. `ORDER BY embedding <=> query_vector` trả kết quả gần nhất lên đầu.
- **Top-k retrieval** — chỉ lấy k kết quả gần nhất (vd k=3-5 bảng) thay vì toàn bộ, để prompt gửi cho Claude chỉ chứa phần schema thực sự liên quan tới câu hỏi.
- **Token budget (prompt size)** — nhồi toàn schema (A1) tốn nhiều token → tăng cost + latency, và có thể "distract" model bằng thông tin không liên quan (càng nhiều context không liên quan, model càng dễ chọn sai bảng/cột). Giảm prompt xuống top-k bảng liên quan giúp cả 3: rẻ hơn, nhanh hơn, và (kỳ vọng) chính xác hơn hoặc ít nhất không tệ hơn A1 — đây chính là câu hỏi buổi này cần đo bằng số liệu (accuracy + token count), không đoán.

## 4. Các bước nhỏ (step-by-step)

1. **Enable pgvector extension**
   - Kết nối Postgres, chạy `CREATE EXTENSION IF NOT EXISTS vector;`
   - Kỳ vọng: `\dx` trong `psql` list ra extension `vector`, không lỗi permission.
   - ⚠️ Lỗi thường gặp: DB managed (RDS/Neon/Supabase...) có thể cần enable qua UI/console trước khi `CREATE EXTENSION` chạy được bằng role thường.
2. **Tạo bảng metadata embedding**
   - Tạo bảng `schema_embeddings (id serial primary key, table_name text, column_name text, description text, embedding vector(384))` — `column_name` nullable (embedding có thể là cấp bảng hoặc cấp cột).
   - Kỳ vọng: bảng tạo xong, cột `embedding` đúng chiều 384 (khớp `all-MiniLM-L6-v2`).
3. **Viết script embed schema (`embed_schema.py`)**
   - Đọc `dictionary.json` → với mỗi bảng (và mỗi cột nếu granularity ở mức cột), ghép `table_name + column_name + description` thành 1 đoạn text ngắn.
   - Encode đoạn text bằng `SentenceTransformer('all-MiniLM-L6-v2').encode(text)` → insert vào `schema_embeddings`.
   - Kỳ vọng: chạy 1 lần, `SELECT count(*) FROM schema_embeddings` khớp số bảng/cột trong dictionary.
   - ⚠️ Lỗi thường gặp: quên insert vector đúng format Postgres (`'[0.1,0.2,...]'::vector`) — driver `psycopg2` cần adapter hoặc cast string thủ công.
4. **Viết retrieval function**
   - Nhận câu hỏi user → encode bằng cùng model → query:
     ```sql
     SELECT table_name, column_name, description
     FROM schema_embeddings
     ORDER BY embedding <=> %s::vector
     LIMIT %s;
     ```
   - Trả về top-k (vd k=5) bảng/cột liên quan nhất.
   - Kỳ vọng: thử vài câu hỏi mẫu, nhìn top-k trả về có "hợp lý" (đúng bảng liên quan tới câu hỏi) bằng mắt trước khi tự động hoá.
5. **Build prompt rút gọn + gọi Claude sinh SQL**
   - Thay vì nhồi toàn `dictionary.json` (cách A1), chỉ đưa vào prompt phần schema của top-k bảng/cột lấy từ bước 4.
   - Giữ nguyên cấu trúc prompt còn lại (system instruction, câu hỏi, format output SQL) giống A1 để so sánh công bằng — chỉ đổi phần "schema context".
   - Kỳ vọng: Claude trả về SQL, format tương tự A1.
6. **Chạy lại 20 câu eval, so sánh với A1**
   - Chạy `eval_a2.py` trên cùng 20 câu hỏi đã dùng ở A1.
   - Với mỗi câu: đo (a) SQL đúng/sai (so kết quả query hoặc so SQL chuẩn, theo cách A1 đã làm), (b) số token của prompt gửi lên Claude (dùng token counter — package đo token của Claude, hoặc ước lượng qua Anthropic API `count_tokens` nếu có).
   - Tổng hợp: accuracy A2, avg prompt tokens A2 → so với accuracy A1, avg prompt tokens A1 đã có từ buổi trước.
   - Kỳ vọng: bảng so sánh 2 dòng (A1 vs A2) với 2 cột số (accuracy, avg tokens).
   - ⚠️ Lỗi thường gặp: quên đảm bảo 20 câu eval A2 giống hệt thứ tự/nội dung câu ở A1 — so sánh lệch bộ câu hỏi sẽ ra kết luận sai.
