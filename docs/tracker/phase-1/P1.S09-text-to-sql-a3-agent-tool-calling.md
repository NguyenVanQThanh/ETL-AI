## 3. Kiến thức quan trọng / Keyword cần nắm

Danh sách khái niệm PHẢI hiểu được (không chỉ copy-paste code) trước khi coi buổi này là xong:

- **Agentic tool-calling** — khác A1 (prompt-only) và A2 (RAG context tĩnh): ở A3, LLM tự quyết định gọi tool nào, thứ tự nào, bao nhiêu lần, dựa vào câu hỏi và kết quả tool trước đó — không có sẵn 1 pipeline cố định.
- **Tool schema (JSON Schema)** — mỗi tool (`list_tables`, `get_schema`, `run_query`) cần định nghĩa `name`, `description`, `input_schema`. Claude chỉ dựa vào field này để quyết có gọi tool và điền argument gì — mô tả tool mơ hồ → model gọi sai/gọi thiếu.
- **`tool_use` / `tool_result` content block** — response từ Claude khi cần gọi tool có `stop_reason: "tool_use"` và 1+ block `tool_use` (tên tool + input JSON). App tự thực thi tool thật rồi gửi lại block `tool_result` (khớp `tool_use_id`) ở request kế tiếp. Model không tự chạy gì — chỉ emit "yêu cầu", code mình chạy thật.
- **ReAct pattern (reason → act → observe)** — mỗi vòng lặp: model *reason* (quyết định cần tool gì), *act* (emit tool_use), code *observe* (chạy tool, trả kết quả) → model tiếp tục reason dựa trên observation mới. Vòng lặp tool-loop chính là hiện thực hoá pattern này.
- **Self-correction / retry loop** — khi `run_query` trả lỗi SQL (cú pháp sai, tên cột sai...), lỗi đó được feed lại cho model qua `tool_result` (đánh dấu `is_error: true`) để model tự sửa SQL và gọi lại `run_query`.
- **Giới hạn retry (2 lần)** — bắt buộc set max retry cho vòng self-correction, tránh vòng lặp vô hạn khi SQL luôn lỗi (model bí, lặp lại cùng lỗi, hoặc lỗi logic không tự sửa được). Hết 2 lần vẫn lỗi → agent trả về thông báo fail rõ ràng, không tự ý bịa kết quả.

## 4. Các bước nhỏ (step-by-step)

1. **Định nghĩa 3 tool**
   - `list_tables()` — trả list tên bảng trong DB (query `information_schema.tables` hoặc catalog tương đương).
   - `get_schema(table: str)` — trả list cột kèm type + description (nếu có comment/metadata) cho 1 bảng.
   - `run_query(sql: str)` — chạy thử SQL qua psycopg, trả kết quả (rows) nếu thành công, hoặc trả message lỗi (không raise crash cả agent) nếu thất bại.
   - Viết JSON Schema (`input_schema`) rõ ràng cho từng tool — đây là thứ Claude dựa vào để gọi đúng.
   - Kỳ vọng thấy: gọi thử từng tool function bằng tay (không qua model) chạy đúng trước khi ghép vào loop.
2. **Viết tool-loop chính**
   - Gửi câu hỏi (system prompt + user question) cho Claude kèm 3 tool schema ở trên (`tools=[...]`).
   - Nhận response, check `stop_reason`. Nếu `"tool_use"` → lấy từng `tool_use` block, thực thi tool thật tương ứng, đóng gói kết quả thành `tool_result` (kèm `tool_use_id`).
   - Gửi lại `tool_result` trong message tiếp theo (role `user`, content là list `tool_result` block) → lặp lại.
   - Kỳ vọng thấy: log rõ mỗi vòng model gọi tool nào, input gì, kết quả gì.
   - ⚠️ Lỗi thường gặp: quên xử lý trường hợp Claude gọi nhiều `tool_use` block cùng lúc trong 1 response → code chỉ xử lý block đầu, bỏ sót block sau.
3. **Self-correction loop khi `run_query` lỗi**
   - Khi `run_query` trả lỗi SQL, đóng gói lỗi vào `tool_result` với `is_error: true` (hoặc field tương đương) để model biết đây là thất bại, không phải data thật.
   - Đếm số lần retry riêng cho case "SQL lỗi" (không tính chung với số vòng gọi tool bình thường). Chạm 2 lần vẫn lỗi → dừng loop, trả về message fail rõ ràng cho user (không tự bịa answer).
   - Kỳ vọng thấy: khi cố ý cho câu hỏi dễ gây SQL sai (vd tên cột không tồn tại), agent tự sửa được trong ≤2 lần, hoặc dừng đúng lúc nếu không sửa được.
   - ⚠️ Lỗi thường gặp: reset retry counter sai chỗ (đếm theo tổng số vòng loop thay vì đếm riêng theo "số lần run_query lỗi liên tiếp") → agent bị dừng sớm hoặc chạy vô hạn.
4. **Ghép câu trả lời cuối**
   - Khi Claude trả response không còn `tool_use` (`stop_reason` khác, thường là `"end_turn"`) → đó là câu trả lời final (SQL cuối +/hoặc kết quả diễn giải bằng lời).
   - Kỳ vọng thấy: agent tự dừng đúng lúc, không gọi tool thừa sau khi đã có đủ thông tin trả lời.
5. **Chạy lại 20 câu eval, so sánh A1/A2/A3**
   - Dùng đúng bộ 20 câu eval từ P1.S07 (A1) / P1.S08 (A2).
   - Với mỗi câu: chạy qua agent A3, ghi lại — đúng/sai, latency (thời gian tổng cả loop), số lần retry SQL đã dùng.
   - Tổng hợp bảng so sánh accuracy + latency trung bình + retry trung bình giữa A1, A2, A3.
   - Kỳ vọng thấy: A3 accuracy ≥ A2 (agent có thể tự sửa lỗi mà A1/A2 không sửa được), nhưng latency A3 cao hơn do nhiều vòng gọi model + tool.

> Step nào có rủi ro/lỗi thường gặp → đã ghi chú "⚠️ Lỗi thường gặp" ngay dưới step đó.
