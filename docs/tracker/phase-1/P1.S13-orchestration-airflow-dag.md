## 3. Kiến thức quan trọng / Keyword cần nắm

Danh sách khái niệm PHẢI hiểu được (không chỉ copy-paste code) trước khi coi buổi này là xong:

- **DAG (Directed Acyclic Graph)** — tập task + quan hệ phụ thuộc, không có chu trình (cycle). Mỗi lần chạy pipeline = 1 DAG file Python định nghĩa cấu trúc, Airflow lo phần schedule/execute.
- **Task dependency (`>>` operator)** — set thứ tự chạy giữa task, vd `ingest_task >> dbt_run_task >> dbt_test_task` nghĩa là `dbt_run` chỉ chạy sau khi `ingest` xong (thành công).
- **retries / retry_delay** — số lần Airflow tự retry task khi fail + thời gian chờ giữa các lần retry (`timedelta`). Buổi này set `retries=2` cho từng task, không cần alerting phức tạp (để Phase 2).
- **Airflow scheduler vs webserver** — scheduler là process quyết định khi nào task chạy (đọc DAG, trigger theo dependency/schedule); webserver là UI (`localhost:8080`) để xem/trigger/theo dõi DAG. Cả 2 chạy như service riêng trong docker-compose.
- **XCom** — cơ chế Airflow cho task truyền data nhỏ cho nhau qua metadata DB. Buổi này KHÔNG cần dùng sâu (3 task chỉ cần chạy tuần tự, không cần trao data qua XCom) — chỉ cần biết nó tồn tại, sẽ dùng kỹ hơn ở Phase 2 khi cần truyền metadata giữa task.
- **BashOperator vs TaskFlow API (`@task` decorator)** — 2 cách viết task tương đương: BashOperator gọi shell command trực tiếp (phù hợp gọi script `ingest.py`/`dbt` có sẵn); TaskFlow API viết task như Python function thuần, Airflow tự lo XCom. Buổi này ưu tiên BashOperator vì mọi step đều là gọi CLI có sẵn (không cần return value giữa task).

## 4. Các bước nhỏ (step-by-step)

1. **Lấy `docker-compose.yaml` chính thức của Airflow**
   - Download trực tiếp từ docs: `curl -LfO 'https://airflow.apache.org/docs/apache-airflow/stable/docker-compose.yaml'` (chạy trong thư mục project, vd `airflow/`).
   - Tạo các dir Airflow yêu cầu: `mkdir -p ./dags ./logs ./plugins ./config` và set `AIRFLOW_UID` theo hướng dẫn trong docs (Linux/Mac cần; Windows Docker Desktop thường không cần).
   - Kỳ vọng: có file `docker-compose.yaml` + 4 dir con trong thư mục Airflow.
   - ⚠️ Lỗi thường gặp: quên tăng RAM Docker Desktop lên ≥4GB → container `airflow-init` hoặc scheduler bị OOM-kill liên tục, log show "exit code 137".

2. **Init Airflow lần đầu**
   - `docker compose up airflow-init` — tạo metadata DB + user admin mặc định.
   - Kỳ vọng: log cuối show "Airflow is ready to go!" hoặc tương đương, exit code 0.

3. **Viết DAG file trong `dags/`** — 3 task nối tiếp
   - Tạo `dags/pipeline_dag.py`, dùng `BashOperator` cho từng step, set `retries=2` (qua `default_args` để áp cho cả 3 task cùng lúc):
     ```python
     from airflow import DAG
     from airflow.operators.bash import BashOperator
     from datetime import datetime, timedelta

     default_args = {
         "retries": 2,
         "retry_delay": timedelta(minutes=2),
     }

     with DAG(
         dag_id="pipeline_ingest_dbt",
         default_args=default_args,
         schedule=None,  # trigger manual, không cần schedule tự động ở buổi này
         start_date=datetime(2026, 1, 1),
         catchup=False,
     ) as dag:
         ingest_task = BashOperator(
             task_id="ingest",
             bash_command="python /path/to/ingest.py",
         )
         dbt_run_task = BashOperator(
             task_id="dbt_run",
             bash_command="cd /path/to/dbt_project && dbt run",
         )
         dbt_test_task = BashOperator(
             task_id="dbt_test",
             bash_command="cd /path/to/dbt_project && dbt test",
         )

         ingest_task >> dbt_run_task >> dbt_test_task
     ```
   - Sửa `/path/to/...` đúng path thật trong project (path phải resolve được TỪ TRONG container Airflow — nếu ingest script/dbt project nằm ngoài container, cần mount volume tương ứng vào `docker-compose.yaml` trước, hoặc chạy ingest/dbt trong cùng container qua image custom).
   - Kỳ vọng: file không lỗi syntax Python (`python dags/pipeline_dag.py` chạy không exception).
   - ⚠️ Lỗi thường gặp: quên mount volume chứa `ingest.py`/dbt project vào container → `BashOperator` fail với "No such file or directory" dù script chạy tay OK ngoài container.

4. **Chạy Airflow**
   - `docker compose up` (hoặc `docker compose up -d` chạy background).
   - Kỳ vọng: `docker compose ps` show `airflow-webserver` và `airflow-scheduler` ở trạng thái `healthy`/`running`.

5. **Trigger DAG qua UI, xem log từng task**
   - Mở `http://localhost:8080` (user/pass mặc định `airflow`/`airflow` theo docker-compose chính thức).
   - Tìm DAG `pipeline_ingest_dbt`, unpause (toggle), bấm trigger (nút ▶) để chạy manual.
   - Click vào từng task box → xem log riêng của `ingest`, `dbt_run`, `dbt_test`.
   - Kỳ vọng: cả 3 task chuyển màu xanh (success) theo đúng thứ tự trái → phải.
   - ⚠️ Lỗi thường gặp: DAG không hiện trong UI → thường do lỗi syntax trong DAG file (check tab "DAG Import Errors" trong UI) hoặc scheduler chưa scan file mới (đợi ~30s hoặc restart scheduler).

## 5. Output mong muốn

- [ ] DAG `pipeline_ingest_dbt` (file `dags/pipeline_dag.py`) trigger manual trên Airflow UI (`localhost:8080`) — cả 3 task (`ingest`, `dbt_run`, `dbt_test`) chuyển **success** theo đúng thứ tự, không task nào bị skip.
- [ ] Mỗi task có `retries=2` set đúng (verify bằng cách xem tab "Details" của task trong UI, field Retries = 2).
- [ ] Verify khả năng chạy lại từ đầu: xoá data raw hiện có (theo đúng path/table ingest ghi vào), trigger lại DAG từ UI → thấy task `ingest` tự chạy lại và tạo lại data raw đúng như trước, `dbt_run`/`dbt_test` tiếp tục chạy PASS trên data mới ingest.
- [ ] File/artifact tạo ra: `dags/pipeline_dag.py`, `docker-compose.yaml` (Airflow) trong thư mục Airflow của project.
