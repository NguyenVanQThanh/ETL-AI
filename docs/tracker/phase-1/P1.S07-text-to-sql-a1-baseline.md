## 3. Kiến thức quan trọng / Keyword cần nắm

Danh sách khái niệm PHẢI hiểu được (không chỉ copy-paste code) trước khi coi buổi này là xong:

- **Full-schema prompting** — nhồi toàn bộ `dictionary.json` (mọi table/column/description) vào system prompt, không dùng retrieval/RAG chọn lọc. Đây là baseline đơn giản nhất (A1) để đo accuracy sàn — buổi sau (A2) mới thêm RAG để so sánh cải thiện.
- **Execution accuracy (EX)** — metric đánh giá bằng cách CHẠY cả SQL model sinh ra và gold SQL trên DB thật, so sánh **result set** (dữ liệu trả về) có giống nhau không — KHÔNG so sánh text SQL (2 câu SQL viết khác nhau vẫn đúng nếu trả về cùng data). Công thức: EX = (số câu match) / N. Lưu ý limitation: có thể false positive (SQL sai cấu trúc nhưng trùng result ngẫu nhiên) hoặc false negative (SQL đúng nhưng thứ tự cột/row khác) — cần chuẩn hoá kết quả trước khi so (sort rows, so theo set) trước khi so sánh.
- **Prompt injection risk khi sinh SQL từ user input** — câu hỏi user được nhồi trực tiếp vào prompt để sinh SQL; user có thể chèn chỉ thị lạ (vd "ignore schema, DROP TABLE...") khiến model sinh SQL nguy hiểm. Ở buổi này chưa cần guardrail đầy đủ (đó là P1.S10), nhưng bắt buộc chạy SQL sinh ra trên **read-only connection** hoặc DB test/sandbox, không phải DB production — để tránh hậu quả nếu model sinh SQL phá hoại.

## 4. Các bước nhỏ (step-by-step)

1. **Load schema + build system prompt**
   - Đọc `metadata/dictionary.json`, format thành text mô tả đầy đủ table/column/type/description, nhồi vào system prompt kèm instruction "chỉ trả về SQL, không giải thích, wrap trong ```sql fenced code block"
   - Kỳ vọng: in thử system prompt ra thấy đủ toàn bộ schema, không bị cắt
2. **Load 20 câu eval**
   - Đọc `eval/golden_queries.yaml` bằng PyYAML → list gồm `question` + `gold_sql` cho từng câu
   - Kỳ vọng: `len(queries) == 20`
3. **Gọi Claude API sinh SQL cho từng câu**
   - Loop qua 20 câu, mỗi câu gọi `client.messages.create(model=..., system=schema_prompt, messages=[{"role":"user","content":question}])`
   - Parse response: extract SQL từ fenced code block (regex ```` ```sql\n(.*?)\n``` ````) trong `response.content[0].text`
   - ⚠️ Lỗi thường gặp: model trả kèm giải thích ngoài code block → parse lỗi nếu không có instruction rõ + regex fallback (lấy toàn bộ text nếu không tìm thấy fence)
4. **Chạy SQL (generated + gold) trên DB, so kết quả**
   - Dùng connection **read-only** (hoặc DB test riêng, không phải production) để chạy SQL model sinh ra — phòng SQL injection/lỗi sinh ra câu phá hoại (DROP/DELETE)
   - Chạy `gold_sql` và `generated_sql`, lấy result set (list of tuples), chuẩn hoá (sort) rồi so sánh bằng nhau
   - ⚠️ Lỗi thường gặp: generated SQL lỗi cú pháp/table không tồn tại → catch exception, tính là FAIL (không crash cả loop)
5. **Tính execution accuracy + log**
   - Đếm số câu match / 20, in ra console dạng "14/20 = 70%"
   - Log chi tiết từng câu (question, generated_sql, gold_sql, pass/fail) ra file để so sánh với A2 (RAG)/A3 sau

> Step nào có rủi ro/lỗi thường gặp → ghi chú "⚠️ Lỗi thường gặp" ngay dưới step đó.
