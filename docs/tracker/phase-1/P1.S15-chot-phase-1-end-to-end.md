## 3. Kiến thức quan trọng / Keyword cần nắm

Danh sách khái niệm PHẢI hiểu được (không chỉ copy-paste code) trước khi coi buổi này là xong:

- **Reproducibility** — pipeline phải chạy lại được từ đầu trên máy sạch, không phụ thuộc state cũ (volume Docker, cache dbt, file tạm còn sót từ buổi trước). Đây là tiêu chí quan trọng nhất của buổi — "chạy được trên máy mình" ≠ "chạy được từ máy mới clone".
- **End-to-end test** — test toàn chuỗi (ingest → transform → agent → API → UI) thay vì test từng phần riêng lẻ như các buổi trước; lỗi tích hợp (vd sai port, sai path env) chỉ lộ ra ở bước này.
- **Execution accuracy tổng hợp** — gộp lại kết quả accuracy của 3 phương pháp A1 (rule-based/template), A2, A3 (agent-based, đã đo riêng ở P1.S7-S9) trên cùng bộ 20 câu eval, để so sánh trade-off cost/latency/accuracy giữa 3 approach trong 1 bảng duy nhất.
- **Definition of done cho 1 phase** — Phase 1 chỉ coi là ✅ khi: repo clone mới chạy end-to-end theo README không cần hỏi thêm, VÀ bảng accuracy đã điền số liệu thật. Thiếu 1 trong 2 → Phase 1 chưa xong, không mở Phase 2.

## 4. Các bước nhỏ (step-by-step)

1. **Dọn sạch state cũ**
   - `docker compose down -v` để xoá volume Postgres/Airflow cũ (hoặc test trên máy/container mới hoàn toàn nếu có thể)
   - Xoá thư mục `dbt/target`, `dbt/dbt_packages` nếu có cache
   - Kỳ vọng: `docker volume ls` không còn volume của project
   - ⚠️ Lỗi thường gặp: quên `-v` → volume cũ vẫn còn, test "reproducibility" bị false positive (chạy được nhưng thật ra đang dùng data cũ)

2. **Chạy lại từ đầu: `docker compose up`**
   - `docker compose up -d` khởi động Postgres (+ Airflow nếu containerized)
   - Kỳ vọng: container healthy, kết nối được `psql` vào DB rỗng (chưa có data)

3. **Ingest data**
   - Chạy lại script/step ingest đã dùng ở P1.S2-S3 (nạp seed data vào Postgres)
   - Kỳ vọng: query thử 1 table raw thấy đúng số dòng như buổi ingest ban đầu

4. **dbt run + test + snapshot**
   - `dbt run` (staging + marts) → `dbt test` → `dbt snapshot` (SCD Type 2 cho `dim_seller`, xem lại P1.S14)
   - Kỳ vọng: `dbt test` PASS 100%, snapshot table có ít nhất 1 record version
   - ⚠️ Lỗi thường gặp: thứ tự sai (`snapshot` trước `run`) → snapshot rỗng vì source table chưa tồn tại

5. **Trigger Airflow DAG**
   - Unpause DAG, trigger run manual (hoặc chờ schedule nếu đã set)
   - Kỳ vọng: DAG run status SUCCESS trên toàn bộ task (ingest → dbt → agent eval nếu DAG có gộp bước này)

6. **Start API (uvicorn) + UI (npm)**
   - `uvicorn app.main:app --reload` (hoặc lệnh đã chốt ở P1.S10) rồi `npm run dev` (P1.S11)
   - Kỳ vọng: UI load được, gọi thử 1 câu hỏi thấy trả lời từ agent qua API

7. **Chạy lại eval 20 câu cho cả 3 agent**
   - Chạy lại `eval_a1.py`, `eval_a2.py`, `eval_a3.py` (script đã có từ P1.S7-S9) trên đúng bộ 20 câu eval
   - Ghi kết quả accuracy (số câu đúng / 20) + latency trung bình mỗi phương pháp vào bảng "Kết quả accuracy A1/A2/A3" trong [de-genai-roadmap-tracker.md](../de-genai-roadmap-tracker.md) (điền số liệu thật — KHÔNG sửa cấu trúc bảng)
   - Kỳ vọng: có đủ 3 dòng số liệu (A1, A2, A3) trong bảng tracker chính

8. **Viết README.md ở root repo**
   - Mô tả kiến trúc tổng thể (sơ đồ text đơn giản: Postgres → dbt → Airflow → Agent A1/A2/A3 → FastAPI → UI), prerequisites (Docker, Python version, Node version, các biến env cần trong `.env`), và đúng thứ tự lệnh chạy full stack như 6 step trên (docker compose up → ingest → dbt run/test/snapshot → trigger Airflow DAG → uvicorn → npm)
   - Kỳ vọng: người khác clone repo mới, đọc README, chạy theo thứ tự — không cần hỏi thêm gì để lên được toàn bộ stack

9. **Review Nhật ký P1.S1-S14, tổng hợp vướng mắc lớn**
   - Đọc lại cột "Vướng mắc" của từng file `P1.S01...` → `P1.S14...`
   - Nếu có vướng mắc lặp lại nhiều buổi (vd: version conflict, port conflict) → ghi tổng hợp ngắn vào Nhật ký buổi này (mục 6) để tham khảo khi vào Phase 2

> Step nào có rủi ro/lỗi thường gặp đã ghi chú "⚠️ Lỗi thường gặp" ngay dưới step đó.
