## 3. Kiến thức quan trọng / Keyword cần nắm

Danh sách khái niệm PHẢI hiểu được (không chỉ copy-paste code) trước khi coi buổi này là xong:

- **Semantic layer / data dictionary** — lớp metadata mô tả bảng/cột bằng ngôn ngữ tự nhiên (business meaning), tách khỏi DDL kỹ thuật. Trong hệ text-to-SQL, dictionary này được nhồi vào prompt cho LLM để model biết "cột `mrr` nghĩa là gì" mà không cần đọc raw schema hoặc suy đoán từ tên cột. Ở Phase 1 dùng JSON tự chế (dictionary.json); MetricFlow (dbt Semantic Layer thật, có `semantic_manifest.json` với `semantic_models`/`metrics`/`entities`/`dimensions`) để Phase 2 mới self-host đầy đủ.
- **`manifest.json` structure** — artifact dbt sinh ra sau `dbt compile`/`dbt docs generate`, nằm ở `target/manifest.json`. Field quan trọng: `nodes` (dict, key = `model.<project>.<model_name>`) chứa `description` (model-level), `columns` (dict, mỗi cột có `description`), `depends_on`. Đây là cách lấy description đã khai báo trong `schema.yml` một cách programmatic, không cần parse YAML thủ công.
- **`information_schema.columns`** — view chuẩn SQL của Postgres liệt kê `table_name`, `column_name`, `data_type`, `is_nullable` cho mọi bảng. Dùng để lấy type CHÍNH XÁC theo DB thật (dbt `manifest.json` có type nhưng đôi khi chỉ suy ra từ SQL, không luôn khớp 100% với DB — kết hợp cả 2 nguồn cho chắc).
- **Execution accuracy (EX)** — metric chuẩn để đánh giá text-to-SQL (dùng ở Spider/BIRD benchmark, sẽ áp dụng ở `P1.S7`): so kết quả THỰC THI của SQL do model sinh ra với kết quả thực thi của gold SQL, KHÔNG so sánh string SQL (vì 1 câu hỏi có thể viết đúng bằng nhiều SQL khác nhau). Vì vậy `golden_queries.yaml` phải lưu SQL "đúng" (gold) để sau này chạy và so kết quả, không phải để so khớp text.
- **Golden query set** — tập câu hỏi ngôn ngữ tự nhiên đi kèm gold SQL, format phổ biến kiểu Spider/BIRD (`question`, `sql`, `db_id`). Buổi này tự soạn 20 cặp làm eval set nội bộ cho project, dùng lại 10 câu đã viết SQL ở P1.S5 (tái sử dụng, đỡ viết lại) + viết thêm 10 câu hỏi tự nhiên mới kèm SQL tương ứng.

## 4. Các bước nhỏ (step-by-step)

1. **Viết `description` cho model + cột trong `schema.yml`**
   - Mở `schema.yml` của các mart model (nơi khai báo model ở P1.S3–S4). Với mỗi model: thêm field `description:` mô tả model làm gì (business meaning, không phải lặp lại tên model).
   - Với các cột QUAN TRỌNG (primary key, cột dùng để join, cột metric chính như revenue/mrr/count...): thêm `description:` trong block `columns:` của từng cột. KHÔNG cần viết description cho mọi cột phụ — ưu tiên cột người dùng cuối (hoặc LLM) sẽ hỏi tới.
   - Kỳ vọng: `dbt docs generate` chạy lại không lỗi, description hiện trong `target/manifest.json` ở field tương ứng.
2. **Chạy lại `dbt docs generate`**
   - Lệnh: `dbt docs generate` — sinh lại `target/manifest.json` với description mới vừa thêm.
   - Kỳ vọng: log không có lỗi compile; `target/manifest.json` có timestamp mới.
3. **Viết script Python đọc `manifest.json` + `information_schema`**
   - Script (vd `scripts/build_dictionary.py`): (a) `json.load()` `target/manifest.json`, lọc `nodes` có `resource_type == "model"`, lấy `name`, `description`, và mỗi cột trong `columns` lấy `name` + `description`; (b) connect Postgres, query `information_schema.columns` lấy `data_type`/`is_nullable` theo `table_name` tương ứng; (c) merge 2 nguồn theo `(table, column)`; (d) ghi ra `metadata/dictionary.json`.
   - ⚠️ Lỗi thường gặp: tên model trong `manifest.json` (schema/alias) có thể khác tên bảng thật trong Postgres nếu dùng `alias`/custom schema — kiểm tra field `relation_name` hoặc `schema`+`alias` trong node để map đúng bảng khi query `information_schema`.
   - Kỳ vọng: file `metadata/dictionary.json` sinh ra, mỗi entry có `table`, `column`, `type`, `description`.
4. **Soạn `eval/golden_queries.yaml` — 20 cặp câu hỏi → SQL**
   - Lấy 10 SQL query đã viết ở `sql/analysis/` (P1.S5), với mỗi query viết lại 1 câu hỏi ngôn ngữ tự nhiên tương ứng (câu hỏi mà SQL đó trả lời) → 10 entry đầu.
   - Viết thêm 10 câu hỏi ngôn ngữ tự nhiên MỚI (chưa có SQL sẵn) — dựa trên các mart model đã có description ở step 1, viết SQL gold tương ứng cho mỗi câu.
   - Mỗi entry format: `id`, `question`, `sql` (gold SQL, thực thi được), `db_id` (tên schema/DB nếu có nhiều nguồn — nếu chỉ 1 DB thì hardcode 1 giá trị cố định).
   - Kỳ vọng: file có đúng 20 entry, không entry nào thiếu `question` hoặc `sql`.

## 5. Output mong muốn

- [ ] `metadata/dictionary.json` tồn tại, mỗi entry có đủ 4 field: `table`, `column`, `type`, `description` — không entry nào `description` rỗng cho cột quan trọng đã khai báo ở step 1
- [ ] `eval/golden_queries.yaml` tồn tại, có đúng **20 entry**, mỗi entry có `id`, `question`, `sql`, `db_id`
- [ ] Verify bằng Python: load 2 file không lỗi cú pháp —
  ```bash
  python -c "import json,yaml; d=json.load(open('metadata/dictionary.json')); g=yaml.safe_load(open('eval/golden_queries.yaml')); assert len(g)==20; print(len(d),'dictionary entries;',len(g),'golden queries — OK')"
  ```
- [ ] (Tuỳ chọn, khuyến nghị) chạy thử từng `sql` trong `golden_queries.yaml` trên DB thật — mỗi câu phải thực thi được không lỗi (chuẩn bị sẵn cho execution accuracy ở `P1.S7`)
